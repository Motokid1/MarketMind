# Implementation decisions and scope

The attached DOCX and numbered spec files remain unchanged. Requirement IDs FR-001–020 come from the DOCX; the numbered pack controls execution order. The implementation chooses HTML export from the permitted PDF/HTML alternative and SQLite only for native development. PostgreSQL 16 is the Compose database.

ADR-001: arithmetic lives in pure decimal analytics. Volatility uses sample standard deviation of simple daily returns annualized with sqrt(252). Returns and drawdown use unadjusted source closes. A volume ratio requires twenty preceding valid sessions and excludes the selected session. A zero-volume baseline produces null. Comparisons use an inner join; portfolio allocations are held from the initial session, not silently rebalanced each day. Fees and corporate-action effects are disclosed.

ADR-002: official Python MCP SDK 1.26 is pinned for compatibility with the deployed NSE servers. Exact tools/list metadata is saved under specs/generated. The current inventory has 21 Bhavcopy and 15 CM Market methods. Reviewed bindings carry the discovered input-schema hash and explicit argument mappings. Startup/on-demand discovery must succeed before invoking live methods. Changed, removed and unmapped methods are disabled. All 19 business capability categories have explicit bindings; output availability is independently gated by verified response shape and date evidence. Out-of-baseline corporate actions, index valuation and unrelated methods stay unmapped.

ADR-003: report writing uses a deterministic grounded template, without a required external model API. The bounded LangGraph resolves intent and symbols, validates the plan, concurrently executes market/history workers, calculates, checks evidence, writes structured claims, checks final compliance and publishes. Text is not interpreted as raw method selection. This makes offline and local execution reproducible and avoids assigning arithmetic to a model. External news and causal explanations are excluded.

ADR-004: source dates and crawl dates are distinct. A CM quote uses stock.latestTimestamp and an index uses nseTimestamp. A daily Bhavcopy date is represented at the conventional 15:30 IST session close and explicitly labeled as date precision, not an observed tick timestamp. Listing freshness uses crawl metadata but exposes identifiers only. A bare historical price or undated 52-week summary is unavailable rather than assigned the requested date. Current movers currently return upstream errors and are shown as unavailable.

ADR-005: raw OHLCV lives only in a bounded TTL memory cache. Persisted reports contain derived claims, metrics, input parameters, schema hashes, source timestamps and payload fingerprints; source values are not a reusable price archive. Historical chunks carry input evidence fingerprints. Long requests are bounded and expose partial coverage when the twelve-call run budget or source availability prevents completing the date range. Saved metrics remain inspectable; re-fetching creates a new run.

API documentation is generated by FastAPI at /docs and /openapi.json. All persisted object lookups enforce identity derived from signed JWTs. Reviewer access requires an explicit report share. Administrators must also be on ADMIN_EMAILS. No raw tool or endpoint is accepted from a research prompt. Streamable HTTP calls do not follow redirects and use only the two specified HTTPS endpoints.
